## الفكرة بصياغة طالب

المنصة تحتاج ثلاثة أشياء لتعمل فعليًا:

1. **قاعدة بيانات** (Postgres على Supabase) فيها جداول: مواد، ملفات، طلاب، تحديثات، مواعيد.
2. **مخزن ملفات خاص** (Storage bucket اسمه `resources`) لا يفتحه أحد برابط دائم.
3. **دخول Google** حتى نعرف من رفع الملف ومن هو الأدمن.

الكود في Next.js جاهز؛ هو «الزبون» الذي يتكلم مع Supabase. بدون المفاتيح، الزبون يعرض الواجهة برسائل ودّية ولا ينهار.

## 1) درس الملفات — ماذا يعني كل ملف؟

### أ) ملفات البيئة (أسرار المشروع)

| الملف | المعنى بالعربي |
|-------|----------------|
| `.env.example` | قالب عام يُرفع مع Git ليشرح للمطورين «ما المتغيرات المطلوبة» |
| `.env.local` | نسختك السرية على جهازك فقط — فيها placeholders الآن، تلصق القيم الحقيقية لاحقًا |
| `src/shared/lib/supabase/config.ts` | حارس ذكي: إذا رأى `YOUR_PROJECT` أو `your_anon_key` يعتبر الإعداد «غير جاهز» ويعيد `null` بدل تعطيل الموقع |

**لماذا placeholders؟** حتى لا نخترع مفاتيح وهمية تبدو حقيقية وتفشل بصمت. التطبيق يتعرّف أنها تجريبية ويعرض شريط «معاينة بدون قاعدة بيانات».

**ماذا ستلصق أنت في `.env.local`؟** (أربع قيم فقط لتشغيل المرحلة 1)

```text
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...        ← anon public من لوحة API
SUPABASE_SERVICE_ROLE_KEY=eyJ...           ← service_role (سرّي جدًا)
ADMIN_EMAIL=بريدك_على_google@gmail.com
```

- بادئة `NEXT_PUBLIC_` = يظهر للمتصفح (لذلك anon فقط، ليس service_role).
- `SERVICE_ROLE` = مفتاح أدمن يتجاوز RLS؛ يُستخدم فقط على السيرفر (رفع، موافقة، Signed URL).

### ب) عملاء الاتصال بـ Supabase

| الملف | متى يُستخدم | تشبيه |
|-------|-------------|--------|
| `client.ts` | زر «دخول Google» في المتصفح | مفتاح الزائر العام |
| `server.ts` | صفحات السيرفر تقرأ الجلسة من الكوكيز | موظف الاستقبال |
| `admin.ts` | عمليات حساسة (طابور، تنزيل موقّع، حذف مرفوض) | مفتاح المدير |

كلها تُرجع `null` إن نقصت المفاتيح → الصفحات تعرض `SupabaseSetupNotice` أو Banner بدل Crash.

### ج) قاعدة البيانات (SQL)

| الملف | دوره التعليمي |
|-------|----------------|
| `supabase/schema.sql` | يبني الجداول + يزرع 7 مواد للفصل (`level2-sem1`) + ينشئ بروفايل تلقائي عند أول Google login |
| `supabase/rls.sql` | قوانين «من يرى ماذا»: الطالب يرى approved؛ يرى مساهماته؛ الأدمن يرى الكل عبر `is_admin` |
| `supabase/STORAGE.md` | تعليمات الـ bucket (ليست SQL — من واجهة Storage) |
| `supabase/storage-policies.sql` | توضيح اختياري: المرحلة 1 تعتمد service_role فلا حاجة لسياسات storage إضافية |

**جداول المرحلة 1 الأهم:**

- `courses` — قائمة مواد الفصل (فيها `semester_key` و `semester_label_ar`).
- `profiles` — ملف الطالب (رقم جامعي، هل أدمن؟).
- `resources` — كل ملف مرفوع وحالته `pending|approved|rejected`.
- `updates_feed` — رسائل «آخر التحديثات» على الرئيسية.
- `exam_events` — مواعيد التقويم.

### د) الربط الحقيقي في الواجهة (ما أنجزناه في الكود)

| الميزة | كيف تعمل الآن |
|--------|----------------|
| Feed على الرئيسية | `page.tsx` يقرأ من `updates_feed` عبر `createAdminClient`؛ يعرض `UpdatesFeed`؛ إن لم تُضبط البيئة يظهر Banner أصفر |
| طابور الأدمن | `GET /api/admin/submissions` يجلب `status=pending` من DB + Signed URL للمعاينة؛ الواجهة في تبويب «طابور المساهمات» |
| Hub + تنزيل | `/hub/[code]` يعرض approved فقط؛ `DownloadButton` يستدعي `/api/resources/[id]/download` فيفتح رابطًا موقّتًا (~10 دقائق) |
| مساهماتي | `/my-submissions` يقرأ صفوف المستخدم؛ بدون env يعرض درس الإعداد |
| التقويم | `/calendar` يقرأ `exam_events` بلطف بدون env |

قائمة المواد في الواجهة تطابق SQL: `src/shared/lib/courses.ts` (`SEMESTER_KEY = level2-sem1`).

## 2) إنشاء مشروع Supabase (نقرًا بنقرة)

1. افتح [https://supabase.com](https://supabase.com) وسجّل دخولك.
2. **New project**.
3. اختر/أنشئ Organization.
4. **Name:** مثلًا `gazameel`.
5. ضع **Database Password** قويًا واحفظه خارج Git.
6. اختر Region قريبًا.
7. **Create new project** وانتظر حتى يصبح Ready (دقيقة أو دقيقتان).

### نسخ المفاتيح (أهم خطوة لك)

1. الشريط الجانبي → **Project Settings** (الترس).
2. **API**.
3. انسخ:
   - **Project URL** → `NEXT_PUBLIC_SUPABASE_URL`
   - **anon public** → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - **service_role** (Reveal) → `SUPABASE_SERVICE_ROLE_KEY`  
     ⚠️ لا تلصقه في كود الواجهة ولا في محادثة عامة.
4. افتح `.env.local` في Cursor واستبدل الـ placeholders بالقيم الحقيقية (لا تترك `YOUR_PROJECT` أو `your_anon_key`).
5. `ADMIN_EMAIL=` = نفس إيميل Google الذي ستدخل به كأدمن.

احفظ الملف ثم أعد تشغيل `npm run dev` — Next يقرأ البيئة عند الإقلاع فقط.

## 3) تنفيذ SQL (الجداول + الأمان)

1. في Supabase: **SQL Editor** → **New query**.
2. افتح على جهازك `supabase/schema.sql` → انسخ **كل** المحتوى → الصق → **Run**.
3. Query جديدة: انسخ `supabase/rls.sql` كاملًا → **Run**.
4. **Table Editor**: تأكد من وجود `courses`, `profiles`, `resources`, `updates_feed`, `exam_events`.
5. افتح `courses`: يجب أن ترى **7 مواد** للفصل الأول.

**لماذا ملفّان؟**  
`schema` = البناء والبذرة.  
`rls` = قوانين الأمان (قابل للتكرار بأمان لأننا نعمل `DROP POLICY IF EXISTS` أولًا).

## 4) Storage bucket (Private) — نقرًا بنقرة

التفاصيل أيضًا في `supabase/STORAGE.md`.

1. الشريط الجانبي → **Storage**.
2. **New bucket**.
3. **Name:** اكتب حرفيًا `resources` (نفس الاسم في الكود: `admin.storage.from("resources")`).
4. **Public bucket:** أطفئه ❌ (Private إلزامي).
5. **Create bucket**.
6. (اختياري) Configuration:
   - File size limit: `15728640` (15MB)
   - MIME: `application/pdf`, `image/jpeg`, `image/png`, `image/webp`

**مسارات يكتبها التطبيق:**

```text
pending/{userId}/{uuid}.pdf     ← مساهمة بانتظار المراجعة
approved/{courseId}/{uuid}.pdf  ← رفع أدمن مباشر
```

**لماذا Private؟** حتى لا يستطيع أحد تخمين رابط ملف pending. التنزيل يتم عبر Signed URL من السيرفر بعد التحقق من الجلسة والحالة.

## 5) تفعيل Google Auth — نقرًا بنقرة

### أ) Google Cloud Console

1. [console.cloud.google.com](https://console.cloud.google.com/) → مشروع جديد أو موجود.
2. **APIs & Services** → **Credentials** → **Create credentials** → **OAuth client ID**.
3. إن طُلب: اضبط **OAuth consent screen** وأضف بريدك كـ Test user إن كان External وفي وضع Testing.
4. Application type: **Web application**.
5. **Authorized redirect URIs** أضف (مهم جدًا — رابط Supabase وليس موقعك مباشرة):

```text
https://YOUR_PROJECT_REF.supabase.co/auth/v1/callback
```

استبدل `YOUR_PROJECT_REF` من الـ Project URL (الجزء قبل `.supabase.co`).

6. انسخ **Client ID** و **Client Secret**.

### ب) داخل Supabase

1. **Authentication** → **Providers** → **Google** → Enable.
2. الصق Client ID و Client Secret → Save.

### ج) رجوع المستخدم إلى Gazameel

1. **Authentication** → **URL Configuration**.
2. **Site URL:** مثلًا `http://127.0.0.1:3044` (أو المنفذ الذي تشغّل عليه المعاينة).
3. **Redirect URLs** أضف:

```text
http://127.0.0.1:3044/api/auth/callback
http://localhost:3000/api/auth/callback
```

(أضف كل المنافذ التي تستخدمها محليًا.)

بعد Vercel أضف أيضًا:

```text
https://YOUR_DOMAIN/api/auth/callback
```

الكود في `login/page.tsx` يوجّه إلى:

`{origin}/api/auth/callback?next=/onboarding`

يعني: بعد Google → رجوع للتطبيق → ثم صفحة الرقم الجامعي.

## 7) اختبار المرحلة 1 من الألف إلى الياء (Checklist)

اطبع هذه القائمة وشِكّ على كل بند:

1. ☐ افتح `/` — اختفى الشريط الأصفر (المفاتيح صحيحة).
2. ☐ `/login` → Google → `/onboarding` (رقم جامعي + مواد).
3. ☐ دخول بإيميل = `ADMIN_EMAIL` → `/admin` يفتح (ترقية `is_admin` تلقائية).
4. ☐ `/admin` → **رفع مباشر** → PDF لمادة → يظهر في `/hub/CODE`.
5. ☐ `/upload` → ارفع ملف → رسالة «قيد المراجعة».
6. ☐ `/my-submissions` → الحالة «قيد المراجعة».
7. ☐ `/admin` → طابور → معاينة موقّتة → **موافقة**.
8. ☐ `/` → سطر جديد في **آخر التحديثات** (من `updates_feed`).
9. ☐ `/hub/...` → **معاينة / تنزيل** يفتح الملف (يلزم تسجيل دخول).
10. ☐ رفض ملف تجريبي → يختفي من الطابور ويُحذف من Storage.

أخطاء شائعة:

| العرض | السبب المحتمل |
|-------|----------------|
| 401 عند التنزيل | لست مسجّل الدخول |
| 503 | مفاتيح ناقصة أو service_role placeholder |
| طابور فارغ دائمًا | لم يُنفَّذ schema أو الرفع فشل قبل الإدراج |
| Google يعيد خطأ redirect | Redirect URI في Google/Supabase غير مطابق للمنفذ |

## 8) خريطة ذهنية للتدفّق (احفظها)

```text
طالب يرفع (/upload)
    → Storage: pending/...
    → DB: resources.status = pending
    → الأدمن يرى الطابور (/admin)
         ├─ موافقة → approved + صف في updates_feed + يظهر في Hub
         └─ رفض → rejected + حذف الملف من Storage

أدمن يرفع مباشرة
    → Storage: approved/...
    → approved فورًا + updates_feed

طالب يفتح المكتبة
    → يرى approved فقط
    → DownloadButton → API يتحقق من الجلسة → Signed URL قصيرة
```
